# Contributing corrections

Evidence quality matters more than catalog size. Do not add a release merely because a headline, benchmark, waitlist, or similar model name exists.

For a correction, provide the model/product name, publisher, exact claim, dated official URL, and proposed replacement. Keep announcements, previews, usable API access, downloadable weights, software releases, and pricing observations distinct.

Do not overwrite original source history to make an assessment look stronger. Never infer subscription entitlement, installed versions, measured performance, or savings from a provider label.

For code changes, run server and browser tests, preserve the read-only allowlists, verify escaping, and check that profiles create no network requests. Any new persistence, telemetry, account connection, paid model call, or arbitrary URL fetch requires a separate design/security review.
